# 小米手环 8 Pro 词典扩充改造报告

日期：2026-10-16
对象：用户上传的两个文件（原始文件名在上传时被系统改名，下称 App 包与安装器）

## 第一阶段：项目分析

### 两个文件的真实身份

| 文件 | 大小 | 真实格式 | 身份 |
| --- | --- | --- | --- |
| upload-A（_____1.0） | 70704 B | ZIP（RPK 结构） | 手环端词典 App：com.givemefive.dic「英汉词典」v1.0.0（versionCode 2），designWidth 336，minPlatformVersion 1200，2023-09-15 由 aiot 工具链 1.0.17 构建 |
| upload-B（__1_1） | 2558604 B | 小米表盘.bin（头 5A A5 34 12） | 「词库安装器」表盘（ID 267130003），内含 Lua 脚本与词库数据 |

### 安装器结构（逐字节解析）

- 0x110 起文件表：8 条记录 × 16B `[0x050000NN][0][blockOffset][blockSize]`；
- 每个 block：`[3B 数据长度 LE][1B 文件名长度][16B 零] + 文件名 + 数据`，共 7 个有效 block：
lua/main1.lua（4298 B Lua 源码，明文）、lua/dic（1690316 B 词库本体）、5 个界面图 block（install/del/runing/success/title.bin）；
- 安装动作（Lua 源码确认）：点后执行
`mkdir -p /data/quickapp/mass/com.givemefive.dic` 与 `cp <表盘目录>/dic → /data/quickapp/mass/com.givemefive.dic/dic.bin`；
按钮则 rm 该文件。这就是"词库释放工具"的全部逻辑，它本身不做转换。

### 手环端读取与查询方式（反编译 pages/index/index.js 确认）

- App 读 `internal://mass/dic.bin`，格式：**UTF-16LE 文本，每条两行「单词\n释义\n」，全表按单词排序**，原版共 40013 条、1690316 字节（已从安装器提取并逐项核对：按行重算字节数与文件大小完全一致）。
- 索引硬编码在 App 代码里：一个 463 项的前缀锚点表（1 字母、2 字母、以及若干 `xy+n` 三字母中点锚点，值为字节偏移）+ 总大小常量 1690316。查询时从锚点起以 200 码元为块顺序扫描：词行以查询词为前缀则收集（最多 4 条），当前词大于查询词立即停止。
- 词长 <3 的路由：2 字母查双字母锚点，1 字母查单字母锚点（'a' 固定从 0 开始）。

### 查询失败的根因（按影响排序）

1. **词库本身缺词**：与 BNC/COCA 高频前 3000 词对照，原版缺约 127 个真实常用词/词形，包括 student、deadline、feedback、download、serendipity，以及 including、organisation、theatre、media 等；现代词（smartphone 等）整类缺失。对照测试集见验证一节。
2. **原版排序不严格**：约 1382 处逆序（短语与撇号词条错位、168 组同词条目不相邻）。扫描的提前停止逻辑依赖有序，逆序会使部分条目被跳过——实测原版在同一回归集（1127 词）上有 70 个查不到（6.2%）。
3. **索引锚点缺失导致整类条目不可达**：原版索引键未加引号地写在 JS 对象里，第二字为空格/撇号的短语（如 "a bad beginning makes a bad ending"、"o'clock"）没有可用锚点，原版中实际查不到。
4. 不是容量/编码问题：释义为 UTF-16LE 中文，无乱码；文件大小常量与格式本身可扩展，但**索引与大小常量在 App 内硬编码，只换词库文件必然错位**——这是改造必须同时动 App 索引的原因。

## 第二阶段：方案比较

| 方案 | 内容 | 结论 |
| --- | --- | --- |
| 只替换安装器中的词库 | 索引偏移全部错位，扫描从词条中间开始，解析错位 | 否决（已由格式分析证伪） |
| 只往原词库尾部追加新词 | App 扫描有大小上限与有序停止，尾部新词不可达 | 否决 |
| 保持每个锚点偏移不变、桶内挤空间 | 600 余锚点逐个配平，收益小且极易出错 | 否决 |
| **重建词库 + 重生成索引并 patch App + 按原结构重打包安装器** | 格式、安装流程、查询算法全不变；索引与词库由同一构建脚本生成并自检 | **采用** |

## 第三阶段：实施

数据源：ECDICT（github.com/skywind3000/ECDICT，**MIT License**，许可证全文随交付附带）。
选词规则（脚本 build_dic.py，参数可调）：
- 原 40013 条全部保留（不覆盖、不删除；排序由不严格改为严格序，内容不变）；
- 新增词元 8968 条：考试标签词（中考/高考/四六级/考研/托福/雅思/GRE）∪ BNC/COCA 词频前 20000 ∪ 牛津核心 ∪ 柯林斯 ≥4 星 ∪ 人工核对的现代常用词清单（FORCE_WORDS，针对 ECDICT 无词频数据的 smartphone 等）；
- 词形条目 3628 条：由 ECDICT exchange 字段生成（过去式/过去分词/现在分词/三单/复数/比较级/最高级），释义为「（词元 的X）+词元简释」，使查词形能直达词元释义（App 前缀检索天然支持，零算法改动）；
- 释义清洗：多行合并、去掉 [网络] 网络释义段、限长（词元 96 字、词形 64 字），适配小屏与体积；
- 英美变体：两个拼写在 ECDICT 中均为独立条目，入选后同时收录（已实测 6 组变体对全部可查）。

产物：
- dic-expanded.bin：52609 条（+31.5%），2543608 B；严格有序。
- 索引重生成（gen_index.py）：627 个锚点（原 463），含带引号的空格/撇号键，修复根因 3。
- App patch（patch_app.py）：仅替换 index.js 中的总大小常量与索引对象，版本号 1.0.0/2 → 1.1.0/3（manifest.json、manifest-watch.json、app.js 内嵌清单同步），其余文件字节不变；META-INF/CERT 中的 hash.json（原包只有该清单文件，无私钥签名字段）按新文件重算 SHA-256。**说明：这不是伪造原作者签名——原包 CERT 仅含哈希清单；若你的安装工具另行校验签名身份，以实测为准。**
- 安装器重打包（patch_installer.py）：只更新 dic block 数据与长度、文件表中 dic 的 size 与其后 block 的 offset；表盘头、Lua、图片 block 逐字节不变（已做往返校验：除 dic 外所有 block 内容与原文件完全一致）。

手环端程序改动说明（任务 3 要求）：除索引/大小常量与版本号外，未改任何页面逻辑与查询算法；包名、词库路径、安装流程、界面全部不变，因此与原安装器/原 App 的组合关系保持：**扩充版 App 必须配扩充版词库使用**（索引与词库成对生成），不要混搭原版。

查询优化评估（任务 4）：大小写——App 键盘只能输入小写，词库词面全小写，实际无大小写问题，未改 App；首尾空格——键盘输入不产生首尾空格，未改；词形与变体——已在数据层解决（见上）；不存在词——模拟验证返回空结果且扫描必然终止（见 T4）；索引——锚点从 463 增至 627 且全量对齐校验。

## 第五阶段：使用说明

1. 先装 App：用你原来装这个词典的同一工具/方式，安装「英汉词典-扩充版-1.1.0.rpk」（另附同内容的.bin 命名副本，按你工具的习惯二选一）。版本号更高，走覆盖安装即可，不必先卸载（若工具提示签名不一致，先卸载旧版再装，词库文件不受影响）。
2. 再装词库：安装「词库安装器-扩充版.bin」表盘并设为当前表盘，点，等成功提示。
3. 打开词典 App，先查 student、smartphone、running（词形）验证，再查几个你以前查不到的词。
4. 回滚：随时可装回原始两个文件恢复原状；原始词库未做任何修改，本目录与脚本均保留原件提取件。

复现构建（在 src/ 目录，Python 3）：
```bash
python3 extract_dic.py <原安装器.bin> dic-original.bin
python3 build_dic.py dic-original.bin ecdict.csv dic-expanded.bin build-stats.json
python3 patch_installer.py <原安装器.bin> dic-expanded.bin installer-expanded.bin
python3 patch_app.py <原App.rpk> dic-expanded.bin app-expanded.rpk
python3 verify_app_sim.py dic-expanded.bin <从RPK提取的索引.json> dic-original.bin verify-report.json
```

失败排错：
- 表盘包被工具拒绝（体积）：把 build_dic.py 的 FREQ_LIMIT 调低（如 12000）重跑全部步骤，可把安装器压回约 3.0MB；仍不行则降到 6000（约 2.8MB）。
- App 装不上/提示签名问题：记录工具给出的原文提示发我，可能需要改走你最初的安装渠道或改版本号策略。
- App 打开提示词库不存在：先确认第 2 步表盘已点且提示成功；再确认没有装回原版安装器覆盖。
- 查不到某个具体词：把词发我，我在模拟器里复现定位（词库缺词、锚点或排序问题可逐项区分）。

## 交付后更正与真机验证结果（2026-10-16 晚）

1. **CERT 结构更正**：原包 META-INF/CERT 并非只有 hash.json——zip 条目后还附有约 2108B
   签名数据（CERT 共 3239B）。第一版重建时丢失签名段，导致手环安装校验失败、崩溃重启。
   修复：用 aiot 工具链 SignUtil.signPackage 对 patch 后内容重新完整签名（工具链自带调试
   证书），产出 v3 签名版后安装成功。注意签名者身份与原作者发布证书不同；本机安装渠道
   只验签名完整性，故可正常安装（已真机证实）。
2. **长扫描问题（v3.1 修复）**：原 App 每次只读 200 码元。st 桶无 stn 中点锚点，
   student 需 113 次分块读取，真机上失败（其余词均 ≤17 次）。将分块常量 200 → 2000 后
   student 降为 12 次读取，全词库最长扫描（pr 桶约 28114 码元）也降至 15 次以内。
   最终版本为 App 1.1.1（versionCode 4）。
3. **真机验证（用户实测）**：feedback（新词）可查 → 新词库生效；deadline / organisation /
   serendipity 可查 → 新 App 索引生效且词库后段完整；装 v3.1 后 student 可查 → 全部打通。
